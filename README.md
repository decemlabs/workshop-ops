# MES · ПРОИЗВОДСТВО

Управление производством: учёт цехов, рабочих и задач по ним.

Что умеет:

- цеха карточками — сколько в каждом рабочих, задач в работе и выполненных;
- рабочие — поиск, сортировка, перевод в другой цех перетаскиванием мышью;
- задачи со статусами «Новая», «В работе», «Выполнено»;
- действия сразу над несколькими строками — удалить, сменить статус, перевести —
  и кнопка «Вернуть», если передумали.

## Технологический стек

| Технология | Назначение |
|---|---|
| **React** | Пользовательский интерфейс |
| **Django** | Backend и бизнес-логика |
| **Django REST Framework** | REST API |

| **Docker** | Контейнеризация приложения |

| **Caddy** | Reverse proxy и HTTPS |

## Запуск

Из программ нужна только Docker Desktop — всё остальное скачается и соберётся само.

### 1. Установить Docker Desktop

Скачать с [docker.com](https://www.docker.com/products/docker-desktop/), установить
и запустить. В верхней строке экрана появится значок кита — значит, Docker работает.

### 2. Открыть терминал в папке проекта

В Finder щёлкнуть по папке проекта правой кнопкой → «Новый терминал по папке».
Все команды ниже вводятся туда: одна команда — Enter — дождаться, пока отработает.

### 3. Создать файл с настройками

```bash
cp .env.example .env
```

### 4. Придумать секретный ключ

```bash
openssl rand -base64 48
```

Команда напечатает строку случайных символов. Скопируйте её и вставьте в файл `.env`
сразу после `SECRET_KEY=`, чтобы получилось `SECRET_KEY=скопированная строка`.
Файл открывается любым текстовым редактором. Если команда не нашлась — подойдёт
любая случайная строка длиной от 50 символов.

### 5. Запустить

```bash
docker compose -f compose.prod.yaml up -d --build
```

Первый раз это занимает несколько минут: скачиваются образы и собирается интерфейс.
Дальше запуск — несколько секунд.

### 6. Завести пользователя

```bash
docker compose -f compose.prod.yaml exec backend python manage.py createsuperuser
```

Спросит имя пользователя, почту (можно пропустить — Enter) и пароль дважды.
Пароль при вводе не отображается, даже точками — это нормально, печатайте вслепую.

### 7. Открыть в браузере

[http://localhost:8080](http://localhost:8080) — войти с именем и паролем из шага 6.
Данных пока нет: начните с кнопки «+ Добавить цех».

## Повседневные команды

Остановить (данные сохранятся):

```bash
docker compose -f compose.prod.yaml down
```

Запустить снова:

```bash
docker compose -f compose.prod.yaml up -d
```

Посмотреть, что происходит внутри — если что-то не открывается:

```bash
docker compose -f compose.prod.yaml logs -f
```

Удалить всё вместе с накопленными данными:

```bash
docker compose -f compose.prod.yaml down -v
```

## Настройки в файле `.env`

| Переменная             | Зачем                                                            |
| ---------------------- | ---------------------------------------------------------------- |
| `SECRET_KEY`           | обязательна, задаётся один раз на шаге 4                          |
| `WEB_PORT`             | порт, на котором открывается программа (по умолчанию 8080)        |
| `ALLOWED_HOSTS`        | адреса, по которым программу пускают открывать                    |
| `HTTPS_ONLY`           | `True`, когда сайт выложен наружу под https                       |
| `CSRF_TRUSTED_ORIGINS` | нужна, только если интерфейс живёт на отдельном домене            |
| `POSTGRES_*`           | имя базы, пользователь и пароль Postgres                          |

## Для разработки

Частые команды собраны в `Makefile` — `make help` покажет список.
Ниже те же команды полностью.

База в контейнере, бэкенд и фронтенд — локально:

```bash
docker compose up -d
```

```bash
cd backend && uv run manage.py migrate && uv run manage.py runserver
```

```bash
cd frontend && bun install && bun run dev
```

Интерфейс открывается на [http://localhost:5173](http://localhost:5173) и сам
проксирует запросы на Django. Команды фронтенда — в [frontend/README.md](frontend/README.md).

Проверки:

```bash
cd backend && uv run pytest
```

```bash
cd frontend && bun run test && bun run typecheck && bun run lint
```

Браузерные тесты (`e2e/`) идут в поднятую связку и проверяют её целиком — вход,
создание цеха, массовые действия с откатом, пагинацию. Перед первым запуском
ставится Chromium, это ~150 МБ:

```bash
make e2e-install
```

```bash
make e2e
```

Прогон идёт в видимом окне браузера. Без экрана — например, по ssh:

```bash
E2E_HEADLESS=1 make e2e
```
