# ADR-006: Отдавать SPA и API с одного origin

## Контекст
Аутентификация построена на сессионной куке и CSRF (ADR-003), а это работает без
дополнительных настроек только когда браузер считает фронт и API одним сайтом.

## Решение
В проде Caddy отдаёт собранную SPA и проксирует `/api`, `/api-auth`, `/admin` и `/static`
на gunicorn — `frontend/Caddyfile`. В разработке то же делает прокси Vite
(`frontend/vite.config.ts`), `changeOrigin` намеренно оставлен выключенным.

## Причины
- Не нужны ни CORS-мидлварь, ни заполнение `CSRF_TRUSTED_ORIGINS`: в
  `settings/production.py` список по умолчанию пуст.
- Разработка и прод ведут себя одинаково — расхождения по кукам не всплывают только на проде.
- Заголовок `Host` не подменяется: Django сверяет `Origin` с хостом запроса, при подмене
  POST-запросы падали бы с «Origin checking failed».

## Последствия
Вынести фронт на отдельный домен или CDN без нового решения нельзя — придётся заполнять
`CSRF_TRUSTED_ORIGINS` и разбираться с куками. Клиентские маршруты вроде `/workshops/3`
отдаются через `try_files {path} /index.html`. Файлы с хешем в имени из `/assets/*`
кешируются навсегда.
