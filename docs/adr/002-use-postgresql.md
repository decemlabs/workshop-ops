# ADR-002: Использовать PostgreSQL как единственное хранилище

## Контекст
Карточка цеха показывает счётчики рабочих и задач по статусам, список рабочих — счётчики
задач и заголовок последней. Номер цеха должен быть уникален, но только среди действующих
цехов. Фоновых задач и рассылок в проекте нет.

## Решение
PostgreSQL 18 (`postgres:18-alpine`), подключение через `DATABASE_URL` и `env.db()`.
Ни кеша, ни брокера очередей: отдельного слоя хранения не заводим.

## Причины
- Частичные ограничения уникальности (`UniqueConstraint` с `condition`) — на них держится
  освобождение номера удалённого цеха, см. ADR-004.
- Оконные функции и скалярные подзапросы позволяют собрать всю статистику в одном запросе:
  `backend/src/apps/workshops/querysets.py`.
- Одна зависимость в compose вместо трёх — связка поднимается на любой машине.

## Последствия
Агрегаты считаются на каждом запросе, а не берутся из кеша: при росте числа цехов первым
упрётся именно этот запрос. Масштабирование ограничено одной БД. Появятся фоновые задачи —
понадобится отдельное решение по брокеру и новый ADR.
