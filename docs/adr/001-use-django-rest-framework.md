# ADR-001: Использовать Django и Django REST Framework

## Контекст
Нужен API для CRUD над цехами, рабочими и задачами: списки с поиском, фильтрами,
сортировкой и постраничной выдачей, плюс интерфейс администратора для правки данных
руками. Разработчик один.

## Решение
Django 6 с Django REST Framework. Монолит с layout `src/config` + `src/apps`,
настройки разбиты на `base.py`, `local.py`, `production.py`.

## Причины
- Админка, ORM и миграции есть из коробки — отдельный интерфейс для данных писать не нужно.
- Фильтрация, поиск и сортировка включаются одной настройкой `DEFAULT_FILTER_BACKENDS`
  в `backend/src/config/settings/base.py`.
- Пагинация с клиентским `page_size` — двадцать строк в `backend/src/config/pagination.py`.
- Разбиение настроек даёт браузерный API в разработке и жёсткий JSON-only в проде.

## Последствия
В проде остаются только `JSONRenderer` и `JSONParser`, `BrowsableAPIRenderer` включается
в `local.py`. Бизнес-логика живёт в querysets и viewsets, отдельного сервисного слоя нет:
пока правил мало, лишний слой только удлиняет путь от запроса к запросу в БД.
