# ADR-003: Аутентификация по сессионной куке вместо JWT

## Контекст
Единственный клиент API — SPA этого же проекта, отдаваемая с того же адреса.
Мобильных приложений и сторонних интеграций не планируется.

## Решение
`SessionAuthentication` с CSRF-защитой и `IsAuthenticated` по умолчанию
(`backend/src/config/settings/base.py`). Вход, выход и текущий пользователь —
`LoginView`, `LogoutView`, `MeView` в `backend/src/apps/users/views.py`.
Фронт шлёт `credentials: 'include'` и заголовок `X-CSRFToken`
(`frontend/src/api/client.ts`).

## Причины
- HttpOnly-кука недоступна JS — украсть её через XSS сложнее, чем токен из localStorage.
- Выход действует немедленно: сессия удаляется на сервере, в отличие от stateless-токена,
  живущего до истечения срока.
- Не нужны ни refresh-флоу, ни хранение и обновление токена на клиенте.
- Django и DRF дают это без дополнительных зависимостей.

## Последствия
Клиент обязан находиться на том же origin, что и API — см. ADR-006. В проде куки
закрываются флагом `Secure` через переменную `HTTPS_ONLY`. `MeView` навешивает
`ensure_csrf_cookie`, чтобы браузер получил CSRF-токен до первого POST. Ответ на неудачный
вход намеренно обезличен: «Неверный логин или пароль».
