# ADR-005: SPA на React с react-query вместо глобального стора

## Контекст
Три ресурса с одинаковым CRUD, списки с пагинацией и поиском, массовые операции с откатом.
Данные почти целиком серверные: собственного состояния у клиента мало.

## Решение
React 19 и TypeScript на Vite, `@tanstack/react-query` как слой серверного состояния.
Redux и прочих глобальных сторов нет. Фабрика `frontend/src/hooks/createResourceHooks.ts`
выдаёт хуки на все три ресурса, `frontend/src/model/useAppModel.ts` держит только состояние
интерфейса — выделение, открытые формы, сортировку.

## Причины
- Кеш, инвалидация, дедупликация запросов и статусы загрузки уже есть в библиотеке;
  в сторе это пришлось бы писать руками.
- Политика запросов задаётся одним местом: `staleTime: 30_000`, retry только на 5xx —
  `frontend/src/app/queryClient.ts`.
- Одинаковый CRUD у ресурсов сворачивается в одну фабрику хуков.

## Последствия
Свежесть данных зависит от ключей инвалидации: пропущенный ключ после мутации оставит
на экране старые числа. Стилей-фреймворка нет — оформление собрано из инлайн-стилей
и CSS-переменных, перенесённых из прототипа (`frontend/src/design/`), эти файлы правятся
только вместе с прототипом.
