# ADR-007: Docker Compose как единица развёртывания

## Контекст
Разворачивать нужно на одной машине и одной командой. Kubernetes, реестр образов и CI
под этот проект не поднимаются.

## Решение
`compose.yaml` — только Postgres для локальной разработки, бэкенд и фронт запускаются
с хоста. `compose.prod.yaml` — `db`, `backend` (gunicorn, 3 воркера) и `web` (Caddy)
с общим томом `staticfiles`. `migrate` и `collectstatic` выполняются в `command` связки,
а не в образе — `backend/Dockerfile`.

## Причины
- Образ остаётся неизменяемым и собирается без доступа к базе.
- Локально не нужно пересобирать контейнеры на каждую правку кода — база в контейнере,
  код на хосте.
- Прод-связка поднимается целиком, поэтому e2e-тесты из `e2e/` гоняются против настоящего
  стека по HTTP, а не против дев-сервера.
- Слой зависимостей в образе отделён от кода: пересобирается только при смене лока.

## Последствия
Миграции идут при каждом старте, поэтому экземпляр бэкенда должен быть один.
Горизонтального масштабирования и деплоя без простоя нет: обновление — это перезапуск
связки. Наружу смотрит Caddy по http, поэтому в локальной прод-проверке `HTTPS_ONLY`
выключают, иначе редирект на https зацикливается.
