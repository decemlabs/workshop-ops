# ADR-004: Мягкое удаление с отменой вместо физического

## Контекст
Интерфейс позволяет выделить и удалить сразу несколько рабочих или задач, и сразу после
этого предлагает кнопку «Вернуть». Промахнуться легко, а история задач нужна для отчётности.

## Решение
Базовый класс `SoftDeleteModel` с полями `is_active` и `deleted_batch` (UUID партии
удаления) — `backend/src/apps/workshops/models.py`. `SoftDeleteMixin` в
`backend/src/apps/workshops/views.py` даёт эндпоинты `bulk-delete` и `restore` с каскадом
по связям, `ActiveFilterMixin` — параметр `?is_active=true|false|all`.

## Причины
- `deleted_batch` помечает одним UUID всё, что удалили одним действием, — восстановление
  возвращает ровно ту же партию, включая задачи скрытых вместе с рабочим.
- Внешние ключи стоят на `PROTECT`: физическое удаление цеха с рабочими всё равно упало бы.
- Задачи уволенного рабочего остаются в базе и доступны при `?is_active=all`.

## Последствия
Любая выборка обязана фильтровать по `is_active` — забытый фильтр покажет удалённые записи.
Номер цеха освобождается сразу после удаления благодаря ограничению
`unique_active_workshop_number`, поэтому при восстановлении `restore` отдельно проверяет,
не занял ли номер новый цех, и отвечает 400 вместо падения на ограничении БД.
Данные накапливаются: чистки по расписанию нет.
